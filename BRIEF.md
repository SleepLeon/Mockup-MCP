# Steering assistant MCP — build brief

## What we're building

A mockup MCP server that powers a conversational weekly steering assistant for media investment decisions. The assistant connects to this MCP, queries synthetic MMM (media mix model) output data, and helps media managers decide where to increase or decrease spend across countries and channels each week.

This is a pitch demo — the data is synthetic but must feel realistic and tell a clear story. The real version would swap the synthetic JSON for a Redshift DB query.

## Synthetic data

### Shape

One row per country × channel combination. ~30 countries × 8 channels = ~240 rows.

### Countries

Use these 30: DE, GB, FR, IT, ES, NL, PL, SE, BE, AT, CH, DK, NO, FI, PT, CZ, HU, RO, GR, IE, SK, HR, SI, LT, LV, EE, BG, RS, UA, ZA

### Channels

8 channels: `paid_search`, `paid_social`, `display`, `video`, `affiliate`, `email`, `influencer`, `programmatic`

### Fields per row

```json
{
  "country": "DE",
  "channel": "paid_search",
  "week": "2026-W22",
  "current_spend": 84000,
  "recommended_spend": 106000,
  "spend_delta": 22000,
  "current_revenue": 285600,
  "incremental_revenue": 74800,
  "roi": 3.4,
  "saturation_pct": 72,
  "action": "increase",
  "confidence": 0.91,
  "notes": "Strong elasticity, 28% below saturation curve"
}
```

### Field definitions

- `current_spend` — actual spend this week in EUR
- `recommended_spend` — MMM recommended spend in EUR
- `spend_delta` — recommended minus current (positive = increase, negative = decrease)
- `current_revenue` — revenue attributed to this channel this week
- `incremental_revenue` — additional revenue if recommended spend is applied
- `roi` — revenue per EUR spent (current)
- `saturation_pct` — how far along the saturation curve (0–100). >85 = over-saturated
- `action` — one of: `increase`, `decrease`, `hold`, `watch`
- `confidence` — model confidence 0–1
- `notes` — one-line human-readable reason

### Seeding rules for the data generator

Make the data tell a clear story for the pitch:

- DE paid_search: under-invested, roi 3.4, saturation_pct 72, action increase, delta +€22k
- PL paid_search: under-invested, roi 3.1, saturation_pct 68, action increase, delta +€18k
- NL paid_social: under-invested, roi 2.7, saturation_pct 61, action increase, delta +€15k
- FR display: over-saturated, roi 0.8, saturation_pct 94, action decrease, delta -€24k
- IT display: over-saturated, roi 0.9, saturation_pct 91, action decrease, delta -€18k
- ES display: over-saturated, roi 0.7, saturation_pct 96, action decrease, delta -€13k
- SE paid_social: approaching saturation, roi 2.1, saturation_pct 82, action watch
- AT paid_search: watch, approaching threshold
- BE display: watch, approaching threshold

All other rows: generate with realistic random values. ROI should vary by channel type — paid_search typically 2.5–4x, paid_social 1.8–3x, display 0.7–2x, video 1.5–2.5x, affiliate 2–3.5x, email 3–6x, influencer 1–2x, programmatic 0.8–1.8x.

## MCP tools

Build these 4 tools in `server.py`. All read from `data/synthetic.json`.

### 1. `get_steering_snapshot`

Returns the full week's data. Used by the assistant at the start of every session to load all context.

**Input:**
```json
{ "week": "2026-W22" }
```

**Output:** array of all rows for that week, sorted by abs(spend_delta) descending.

---

### 2. `get_country_channel`

Returns filtered rows for a specific country, channel, or both.

**Input:**
```json
{
  "country": "DE",         // optional, ISO 2-letter
  "channel": "paid_search" // optional
}
```

**Output:** matching rows with full field set.

---

### 3. `run_scenario`

Simulates a budget reallocation. Takes a list of spend changes and returns projected revenue impact.

**Input:**
```json
{
  "changes": [
    { "country": "DE", "channel": "paid_search", "new_spend": 114000 },
    { "country": "FR", "channel": "display",     "new_spend": 60000  }
  ]
}
```

**Output:**
```json
{
  "changes": [...],           // echo input with current_spend for comparison
  "total_incremental_revenue": 112400,
  "total_spend_delta": 0,     // net spend change (should be ~0 for reallocation)
  "summary": "Shifting €54k from FR display to DE paid search projects +€112k incremental revenue. DE stays below saturation at this level."
}
```

Revenue calculation: for each change, use the row's ROI and a simple saturation dampening factor. If new_spend > recommended_spend, apply a 0.6x dampening to the excess (diminishing returns). If new_spend < current_spend, revenue loss = spend_reduction × roi × 0.9.

---

### 4. `get_saturation_flags`

Returns all rows where action is `decrease` or `watch`, sorted by saturation_pct descending. Used for the assistant's proactive opening warning.

**Input:** none (or optional `threshold: 80` to filter by saturation_pct)

**Output:** filtered rows with country, channel, action, saturation_pct, roi, notes.

## System prompt

Save as `system_prompt.md` and reference in README. Use this as the starting point:

```
You are a weekly media steering assistant. Your job is to help media managers 
make fast, confident investment decisions at the start of each week.

You have access to MMM (media mix model) output data via MCP tools. The data 
covers ~30 countries and 8 channels with spend recommendations, ROI estimates, 
and saturation signals for the current week.

At the start of every session:
1. Call get_steering_snapshot to load the full week's data
2. Call get_saturation_flags to identify urgent over-saturation signals
3. Open with a 3-5 sentence headline brief: what's the biggest opportunity, 
   what's over-saturated, and what's the recommended reallocation
4. Show the top 5-8 priority actions as a ranked list with country, channel, 
   action direction, spend delta, ROI, and a one-line reason

When the user asks about a specific country or channel, call get_country_channel.

When the user proposes a budget shift or scenario, call run_scenario and 
explain the projected impact clearly — include whether the new spend level 
stays below the saturation curve.

Tone: direct and actionable. You are talking to media managers in a Monday 
morning steering meeting. Skip caveats unless the model confidence is below 0.7.
Flag low confidence explicitly when it matters.

Currency: always EUR. Abbreviate large numbers (€22k not €22,000).

Never dump raw JSON. Always synthesise tool output into plain English with 
numbers inline.
```

## Stack

- Python 3.11+
- `mcp` package — `pip install mcp`
- No other dependencies needed for the mockup (data is local JSON)

## Running locally

```bash
pip install mcp
python generate_data.py   # creates data/synthetic.json
python server.py          # starts MCP server on stdio
```

## Connecting to Claude

In your Claude Desktop or Claude Code MCP config:

```json
{
  "mcpServers": {
    "steering": {
      "command": "python",
      "args": ["path/to/steering-mcp/server.py"]
    }
  }
}
```
